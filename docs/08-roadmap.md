# 08 · 路线图与开放问题

## 分阶段

时间估算按 **1 名全职 Web3 工程师** 计。有第二人时 M1/M2 可并行压缩约 30%。

### M0 · 地基（2 周）

- [ ] 确认链选型（本文档 02 的决策需与产品/商务确认，尤其是版税不强制这一条）
- [ ] Foundry 工程骨架 + CI（lint / test / gas snapshot / Slither）
- [ ] `AccessRegistry` + `SkinCollection` + `SkinRegistry` 首版，部署到 Base Sepolia
- [ ] indexer 骨架：能把 Transfer 事件写进 Postgres

**验收**：测试网上能手动 mint 一件皮肤，indexer 在 30 秒内反映到数据库。

### M1 · 最小闭环（4 周）

- [ ] `RewardClaim` voucher 路径 + KMS 签名服务
- [ ] settlement 服务 + `pending_rewards` 状态机（含 held 闸门）
- [ ] inventory API + `entitlement-check`
- [ ] indexer reorg 处理与回滚
- [ ] Unity SDK 的只读部分（GetInventory + bundle 加载与哈希校验）

**验收**：测试网完整走通 —— 打一局 → 后台出现待领奖励 → 领取 → 皮肤出现在 Unity 衣柜里并正确渲染。

### M2 · 玩家可用（4 周）

- [ ] Coinbase Smart Wallet 接入 + SIWE 绑定流程
- [ ] Paymaster 接入与预算控制
- [ ] `CrateCollection` + `CrateOpener` 提交-揭示开箱
- [ ] Unity 端绑定钱包与领奖 UI
- [ ] 降级路径实现与演练（05 的降级表逐条验证）

**验收**：一个没有任何加密货币经验的测试玩家，能在 3 分钟内完成绑定并领到第一件皮肤，全程不接触助记词、不支付 gas。这是这个阶段唯一有意义的验收标准。

### M3 · 流通（3 周）

- [ ] EIP-2981 版税配置与收款地址
- [ ] Merkle 赛季 drop（`setSeasonRoot` + proof 生成服务）
- [ ] 在测试网市场完成挂单/成交，验证元数据在第三方市场正确展示
- [ ] 官网 item 展示页（`external_url` 落地页）

**验收**：一件皮肤能在第三方市场挂单、成交，买方在游戏内立即可用（indexer 捕获转移后 inventory 更新）。

### M4 · 上线（4–6 周，含外部依赖）

- [ ] 外部审计（预约需提前，主流机构排期常在 4–8 周以上）
- [ ] 审计问题修复 + 复审
- [ ] 主网部署，所有权移交 Timelock
- [ ] Bug bounty 上线
- [ ] 07 的上线检查清单全部勾选

## 与游戏侧的依赖

Web3 侧无法独立完成的部分，需要与其他人对齐：

| 依赖 | 对方 | 何时需要 |
|------|------|---------|
| 对局结果推送接口 | 游戏服务器 | M1 开始前 |
| 反作弊评分接口（供 held 闸门判定） | 游戏服务器 | M1 |
| 皮肤 AssetBundle 打包流程 + 哈希产出 | 客户端/美术 | M1 |
| 大厅 UI（衣柜、领奖、绑定钱包） | 客户端 | M2 |
| 匹配阶段预热下载 | 客户端 | M2 |
| 玩家账号体系（playerId、注册门槛） | 后端 | M0 就要确认，因为奖励绑定在 playerId 上 |

**最需要早对齐的是最后一条**：奖励绑定 playerId 而非钱包地址，这个决定影响账号系统的设计。

## 开放问题（需要决策，不是我一个人能定的）

1. **是否发行同质化代币？** 本设计明确不发（01）。若商业上必须发，整个合规、经济模型、反刷设计要推倒重来，需要尽早明确。
2. **版税不强制是否可接受？** 04 的决策是宁可少收版税也不限制转移自由。若商务坚持强制版税，需接受 ERC-721C 之类方案对流通的限制，并修改对外承诺措辞。
3. **开箱功能的目标地区？** 直接决定 `CrateOpener` 是否需要地区开关，以及概率公示的形式。属法务范畴但技术上必须提前知道。
4. **首发皮肤的发行量与定价策略？** `maxSupply` 上链后只能下调，定得太高无法回收。需要经济模型输入。
5. **玩家换绑钱包的策略？** 当前设计是 7 天冷却 + 邮件确认。若客服压力大可能需要人工通道，但人工通道本身是攻击面。
6. **停服承诺写到什么程度？** "元数据永久可访问"意味着要预付多年的 IPFS pin 费用并写进用户协议。需要确认愿意承诺多久。

## 明确不做的（v1）

写下来避免反复被提起：

- 多链部署 —— 复杂度远超收益
- 自建 NFT 市场 —— 流动性做不过 OpenSea
- 链上战斗记录 / 链上战绩 —— 成本高、无人消费
- 质押 / 挖矿 / 收益类玩法 —— 与"好游戏 + 真实所有权"的定位冲突，且引入证券风险
- Chainlink VRF —— 提交-揭示已足够，v2 再评估
